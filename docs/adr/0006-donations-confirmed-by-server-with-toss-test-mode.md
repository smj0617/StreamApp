# 후원은 토스페이먼츠 테스트 모드로 결제하고, 서버가 승인을 확인한 뒤에만 확정한다

과제 ④에서 방송자에게 후원하는 기능을 더한다. 실제 돈은 오가지 않아야 하고, 화면의 성공 표시만으로 후원을 확정하면 안 되며, 같은 승인 통지가 여러 번 와도 한 번만 적립해야 한다.

- **결제 서비스**: 토스페이먼츠 결제창(JavaScript SDK v2, API 개별 연동 키)을 테스트 키로 쓴다. 국내 카드·간편결제 테스트 결제창이 바로 뜨고, 회원가입만 하면 테스트 상점 키·웹훅을 쓸 수 있다. 키는 환경변수(`STREAMAPP_TOSS_CLIENT_KEY`, `STREAMAPP_TOSS_SECRET_KEY`)로만 받고, `test_`로 시작하지 않으면 결제를 켜지 않는다. 키가 없으면 후원 내역은 보이고 후원 칸 대신 설정 안내가 보인다.
- **주문은 서버가 만든다**: 화면은 방송과 금액만 고르고 `POST /api/donations/prepare`를 부른다. 서버가 받는 채널(방송의 채널 = 방송 주인)을 정하고, 금액(1,000~1,000,000원)·메시지를 확인해 무작위 주문번호로 `pending` 주문을 만든다. 화면은 이 주문 그대로 결제창을 연다.
- **확정은 서버가 승인을 확인한 뒤에만**: 결제창이 성공 주소로 돌아오면 화면은 받은 `paymentKey`·`orderId`·`amount`를 `POST /api/donations/confirm`으로 넘기기만 한다. 서버는 (1) 주문한 사람인지, (2) 돌아온 금액이 주문 금액과 같은지 보고(다르면 승인 요청 없이 실패로 닫는다), (3) 주문 금액으로 결제 승인 API를 부른 뒤, (4) 결제 서비스가 돌려준 주문번호·금액·상태(`DONE`)와 (5) 받는 채널이 지금도 그 방송의 채널인지 확인한 다음에만 `confirmed`로 바꾼다. 내역과 합계에는 `confirmed`만 들어간다.
- **승인 통지(웹훅)**: 결제 서비스의 `PAYMENT_STATUS_CHANGED` 웹훅을 `POST /api/payments/toss/webhook`으로 받는다. 본문은 누구나 보낼 수 있으므로 결제 키만 꺼내고, 그 키로 결제를 조회한 결과로 성공 주소와 같은 확정 경로를 탄다. 사용자가 성공 주소로 돌아오지 못해도(창을 닫음, 네트워크) 웹훅으로 확정된다.
- **중복 적립 방지**: 확정은 `UPDATE … WHERE order_id = ? AND status <> 'confirmed'` 한 번이고, `order_id`·`payment_key`는 UNIQUE다. 새로고침, 웹훅 재전송, 성공 주소와 웹훅의 경쟁, 동시 요청 모두 한 번만 바뀌고 나머지는 "이미 처리됨"으로 돌아간다. 결제 승인 요청에는 주문번호를 멱등키(`Idempotency-Key`)로 붙이고, 이미 승인된 결제(`ALREADY_PROCESSED_PAYMENT`)는 조회로 바꿔 확인한다.
- **취소·실패**: 결제창을 닫거나(PC `USER_CANCEL`) 실패 주소로 돌아오면 `pending` 주문을 `canceled`·`failed`로 닫는다. 화면의 실패 표시로 `confirmed`를 되돌리지는 않는다. 반대로 결제 서비스가 승인했다고 확인되면 이미 닫힌 주문이라도 확정한다(실제로 결제되었다).
- **결제 서비스 포트**: 앱 서비스는 `PaymentGateway`(승인·조회)만 알고, 토스페이먼츠 HTTP 클라이언트는 서버 어댑터다. 앱 서비스 테스트는 가짜 결제 서비스를, HTTP 테스트는 가짜 토스페이먼츠 서버를 쓴다.

하지 않은 것: 결제 취소(환불)·부분 취소, 금액이 어긋난 승인 결제의 자동 취소(로그와 `failed` 기록만 남긴다), 가상계좌, 후원 알림(채팅·화면 효과), 정산, 방송자별 전체 후원 합계.
