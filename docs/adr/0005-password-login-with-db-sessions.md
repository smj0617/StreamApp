# 비밀번호 로그인과 DB 세션으로 현재 사용자를 정한다

과제 ③에서 [ADR 0001](0001-start-without-auth.md)의 "닉네임만 고르기"를 실제 로그인으로 바꾼다. 사용자 모델(사용자 1명 = 채널 1개)은 그대로 두고 "현재 사용자를 어떻게 정하느냐"만 바꾼다.

- **회원가입·로그인**: 닉네임(기존 규칙)과 비밀번호(8~64자)로 한다. 비밀번호는 Argon2id 해시(PHC 문자열)로만 저장한다. 로그인 실패는 닉네임이 없든 비밀번호가 틀리든 같은 사유("닉네임 또는 비밀번호가 맞지 않습니다", 401)로 알린다.
- **세션**: 로그인하면 무작위 토큰(43자)을 만들어 `streamapp_session` 쿠키(HttpOnly, SameSite=Lax, Path=/, 30일)로 준다. DB `sessions`에는 토큰의 SHA-256만 저장한다. 요청마다 서버가 토큰으로 사용자를 찾으므로 쿠키를 고쳐 다른 사용자가 될 수 없다. 로그아웃은 DB의 세션을 지우고 쿠키도 지운다. JWT 대신 DB 세션을 고른 이유는 로그아웃을 즉시 반영하고, 이미 SQLite가 있어 추가 비밀 값(서명 키)이 필요 없기 때문이다.
- **권한 확인 위치**: 서버 함수·axum 어댑터(녹화방송 올리기, 휴대폰 방송 중계, 채팅)는 세션으로 로그인 여부만 확인하고(401) 사용자 ID를 앱 서비스에 넘긴다. 방송 주인·댓글 작성자 확인(403)은 앱 서비스가 한다. 화면의 버튼 숨기기는 편의일 뿐이다.
- **이전 단계 사용자**: 비밀번호 없이 만든 사용자(`password_hash`가 NULL)에게는 앱이 시작할 때 기본 비밀번호(`STREAMAPP_DEFAULT_PASSWORD`, 기본 `test1234`)를 넣는다. 빈 DB의 기본 사용자 철수·영희·민수도 같은 비밀번호다. 로컬 개발·확인용 시험 값이며, 실제로 쓰는 서버라면 바꾸거나 기본 사용자를 지운다.
- **CSRF**: SameSite=Lax 쿠키라 다른 사이트에서 보낸 POST에는 세션이 실리지 않는다. 별도 CSRF 토큰은 두지 않는다.

하지 않은 것: 비밀번호 변경·재설정, 로그인 시도 횟수 제한, 회원 탈퇴, 관리자 권한.
