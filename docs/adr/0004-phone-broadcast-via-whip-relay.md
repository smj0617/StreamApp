# 휴대폰 방송은 브라우저 WebRTC(WHIP)로 MediaMTX에 보내고, 시작 요청은 앱이 중계한다

휴대폰 방송은 앱을 설치하지 않고 휴대폰 브라우저의 앱 페이지(`/broadcast`)에서 한다. 브라우저가 카메라·마이크를 열어(`getUserMedia`) WebRTC로 보낸다. 송출 시작 요청(WHIP, SDP 제안)은 앱의 `/api/broadcast/whip`으로 보내고, 앱은 쿠키의 현재 사용자 채널을 찾아 `http://127.0.0.1:8889/<채널ID>/whip?key=<송출 키>`로 넘긴다. 영상·소리는 휴대폰이 MediaMTX의 ICE 포트(8189)로 직접 보낸다. 송출 키 확인과 라이브 시작·종료는 OBS 송출과 똑같이 MediaMTX의 HTTP 인증과 훅이 맡는다(ADR 0002). 그래서 라이브·시청·채팅 코드는 바뀌지 않는다.

- **송출 키를 휴대폰에 보내지 않는다.** 앱이 서버에서 붙인다. MediaMTX가 돌려주는 세션 주소의 `?key=`도 떼고 돌려준다.
- **영상은 H.264로만 보낸다.** MediaMTX가 시청용 HLS로 바꿀 수 있어야 하기 때문이다(VP8은 바꿀 수 없다). 소리는 Opus이며 HLS(fMP4)에 그대로 들어간다.
- **휴대폰과 PC는 같은 와이파이에 있어야 한다.** MediaMTX가 알려 주는 ICE 후보는 PC의 사설 IP다. STUN·TURN 서버는 두지 않았다.
- **휴대폰 페이지는 HTTPS로 열어야 한다.** 휴대폰 브라우저는 보안 출처(HTTPS·localhost)에서만 카메라를 연다. 앱은 HTTPS를 직접 제공하지 않고, 개발할 때는 터널(cloudflared)로 HTTPS 주소를 만든다. 시작 요청이 앱을 거치므로 HTTPS 주소는 앱 하나만 있으면 된다.

## Considered Options

- **휴대폰에서 RTMP 앱(Larix 등)으로 송출**: 지금 OBS 경로를 그대로 쓸 수 있지만, 과제가 요구하는 "카메라·마이크로 송출을 시작·종료하는 코드"가 앱에 없게 된다.
- **MediaMTX 내장 송출 페이지(`:8889/<경로>/publish`)**: 코드가 거의 없지만, 송출 키를 휴대폰에서 직접 다뤄야 하고 MediaMTX에도 따로 HTTPS 인증서를 설정해야 한다.
- **브라우저가 MediaMTX WHIP에 직접 요청**: 중계가 필요 없지만, 송출 키가 브라우저로 가고 MediaMTX 포트(8889)에도 HTTPS가 필요하다.
- **앱이 미디어까지 받기(webrtc-rs 등)**: ADR 0002에서 영상은 MediaMTX에 맡기기로 했다.
