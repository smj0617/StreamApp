# 녹화방송 영상 파일은 앱이 받아 저장하고 내준다

녹화방송은 사용자가 올린 영상 파일(mp4·webm)을 앱이 직접 받아 녹화방송 폴더(기본 `data/recordings`, 환경변수 `STREAMAPP_RECORDINGS_DIR`)에 무작위 이름으로 저장하고, DB에는 제목과 그 파일 이름(영상 위치)을 남긴다. 시청자 브라우저는 앱이 내주는 `/media/recordings/<파일 이름>`을 `<video>`로 바로 재생하며, 되감기·건너뛰기는 Range 요청으로 처리한다. 라이브 영상은 계속 MediaMTX가 맡으므로, ADR 0002의 "앱은 영상을 다루지 않는다"는 라이브에만 적용된다.

올리기는 서버 함수가 아니라 axum 라우터의 멀티파트 POST로 받는다. 큰 파일을 메모리에 모으지 않고 조각마다 바로 파일로 쓰려는 것이다. 파일 저장과 규칙 확인(제목, 확장자, 크기, 사용자)은 앱 서비스가 맡는다. 그래서 HTTP 없이도 테스트할 수 있다. 실패한 등록은 쓰다 만 파일을 남기지 않는다.

## Considered Options

- **저장된 영상 주소만 등록**: 앱이 영상 바이트를 전혀 다루지 않아 ADR 0002와 맞는다. 하지만 사용자가 영상을 어딘가에 미리 올려 두어야 해서, 로컬에서 바로 등록·재생을 확인하기 어렵다.
- **MediaMTX에 맡기기**: MediaMTX는 송출을 받거나 자기가 녹화한 파일을 내줄 뿐이고, 올린 파일을 받는 기능은 없다.
- **업로드 후 HLS로 변환(ffmpeg)**: 화질 선택이나 긴 영상에는 낫지만, 지금은 브라우저가 그대로 재생하는 mp4·webm만 받으면 충분하다.
- **오브젝트 스토리지(S3 등)**: 배포할 때는 맞지만 로컬 실행에 외부 서비스와 비밀 값이 필요해진다. 저장 위치는 앱 서비스 안에 모여 있어 나중에 바꿀 수 있다.
